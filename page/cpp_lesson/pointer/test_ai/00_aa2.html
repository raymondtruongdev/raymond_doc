C & C++ Programming

Con Trỏ trong C
Hướng dẫn toàn diện

Từ khái niệm cơ bản đến nâng cao — hiểu rõ bộ nhớ, pointer, và cách sử dụng hiệu quả. Dành cho người mới bắt đầu.

1

Biến và Bộ nhớ

Trước khi học về con trỏ, bạn cần hiểu cách máy tính lưu trữ biến trong bộ nhớ. Mỗi biến bạn khai báo sẽ được cấp phát một vị trí trong bộ nhớ (memory address).

Biến int a = 5 không chỉ chứa giá trị 5, mà còn có một địa chỉ cụ thể trong RAM. Địa chỉ này là một con số hexa (ví dụ 0x7ffee4b8a9bc) xác định vị trí của ô nhớ đó.

Sơ đồ bộ nhớ cho biến int a = 5
Địa chỉ ───▶
0x7ffee4
← Địa chỉ bộ nhớ (memory address)
Giá trị ───▶
5
← Giá trị lưu trong ô nhớ đó

Bộ nhớ máy tính được chia thành các vùng chính, mỗi vùng có mục đích và cách quản lý riêng:

graph TD A[Memory] --> B[Stack] A --> C[Heap] A --> D[Data Segment] A --> E[Code Segment] B --> B1[Biến cục bộ] B --> B2[Tham số hàm] B --> B3[Địa chỉ trả về] C --> C1[malloc / new / calloc] C --> C2[Dynamic memory] D --> D1[Biến global] D --> D2[Biến static] E --> E1[Mã máy] E --> E2[Code chương trình]
Vùng nhớ Đặc điểm Quản lý
Stack Lưu biến cục bộ, tham số hàm, địa chỉ trả về. Kích thước nhỏ (~8MB). Tự động — cấp phát khi hàm được gọi, giải phóng khi hàm kết thúc.
Heap Lưu dữ liệu cấp phát động. Kích thước lớn, có thể mở rộng. Thủ công — bạn phải tự gọi malloc() và free().
Data Segment Lưu biến global, biến static. Tự động — tồn tại suốt vòng đời chương trình.
Code Segment Chứa mã máy (instructions) của chương trình. Chỉ đọc, cố định.
💡

Stack: Tự động quản lý, biến cục bộ được cấp phát và giải phóng tự động. Nhanh nhưng kích thước hạn chế.
Heap: Bạn phải tự quản lý bằng malloc() và free(). Linh hoạt nhưng chậm hơn và dễ gây lỗi (memory leak, dangling pointer).

2

Pointer cơ bản — Con trỏ là gì?

Con trỏ (pointer) là một biến lưu địa chỉ bộ nhớ của một biến khác, thay vì lưu giá trị trực tiếp. Nó "trỏ đến" vị trí của biến kia.

Nếu int a = 5 lưu giá trị 5 tại một ô nhớ nào đó, thì int *p = &a lưu địa chỉ của a (tức là số của ô nhớ đó).

Ví dụ cơ bản về pointer 
#include 

int main() {
    int a = 5;        // Biến a chứa giá trị 5 tại một ô nhớ
    int *p = &a;      // p là con trỏ, chứa địa chỉ của a

    printf("Giá trị của a: %d\n", a);           // 5
    printf("Địa chỉ của a: %p\n", &a);          // 0x7ffee4 (ví dụ)
    printf("Giá trị của p: %p\n", p);           // 0x7ffee4 (giống &a)
    printf("Giá trị tại địa chỉ p trỏ tới: %d\n", *p); // 5

    return 0;
}
Kết quả
Giá trị của a: 5
Địa chỉ của a: 0x7ffee4b8a9bc
Giá trị của p: 0x7ffee4b8a9bc
Giá trị tại địa chỉ p trỏ tới: 5
Sơ đồ pointer trỏ đến biến a
a ───▶
5
← Biến a tại địa chỉ 0x1000
p ───▶
0x1000
← p chứa địa chỉ của a
*p dereference ──────────────▶ Đi đến địa chỉ 0x1000, lấy giá trị 5
💡

Hình dung đơn giản: Hãy tưởng tượng bộ nhớ là một dãy tủ có khóa. Biến int a là một ngăn tủ có nhãn "a" chứa số 5. Con trỏ int *p là một mảnh giấy ghi "số tủ: 0x1000" — nó không chứa số 5, mà chỉ ghi địa chỉ của ngăn tủ chứa số 5.

3

Các kiểu khai báo Pointer

Có nhiều cách viết khai báo con trỏ trong C/C++. Tất cả đều đúng, nhưng ý nghĩa và thói quen sử dụng khác nhau:

Kiểu khai báo Ý nghĩa Ghi chú
int* p; p là con trỏ đến int Style phổ biến trong C++, nhấn mạnh "int*" là kiểu pointer
int *p; p là con trỏ đến int Style truyền thống trong C, dấu * gắn với biến
int * p; p là con trỏ đến int Có khoảng trắng ở cả hai bên, ít dùng

📌 CẢNH BÁO QUAN TRỌNG: Phân biệt int* p1, p2

⚠️

Lỗi rất phổ biến ở người mới: Khi khai báo nhiều biến trên cùng một dòng với int* p1, p2, chỉ p1 là con trỏ, còn p2 là int bình thường! Dấu * chỉ gắn với biến đầu tiên, không áp dụng cho các biến sau.

Lỗi thường gặp khi khai báo nhiều pointer 
// ❌ SAI - Chỉ p1 là pointer, p2 là int bình thường!
int* p1, p2;

// ✅ ĐÚNG - Cả hai đều là pointer
int *p1, *p2;

// ✅ ĐÚNG - Khai báo riêng rõ ràng
int* p1;
int* p2;

// ❌ Cũng sai tương tự
int *p1, p2;   // p2 là int, không phải pointer
Phân tích: int* p1, p2;
p1 ───▶
pointer to int
← Là con trỏ, lưu địa chỉ
p2 ───▶
int
← Là int bình thường, KHÔNG phải pointer!
✅

Best practice: Luôn khai báo mỗi biến trên một dòng riêng. Điều này tránh nhầm lẫn và giúp code dễ đọc hơn.

4

Ý nghĩa của * và &

Hai toán tử quan trọng nhất khi làm việc với con trỏ là & (address-of) và * (dereference). Hiểu rõ chúng là chìa khóa để làm chủ pointer.

📌 Toán tử & — Lấy địa chỉ (Address-of)

Toán tử & trả về địa chỉ bộ nhớ của biến. Nó cho bạn biết biến đó nằm ở ô nhớ nào trong RAM.

Toán tử & — Lấy địa chỉ 
#include 

int main() {
    int a = 10;
    int *p = &a;  // &a = lấy địa chỉ của a

    printf("a = %d\n", a);        // 10
    printf("&a = %p\n", &a);      // 0x7ffee4b8a9bc (địa chỉ của a)
    printf("p = %p\n", p);        // 0x7ffee4b8a9bc (p chứa địa chỉ của a)

    return 0;
}

📌 Toán tử * — Dereference (Giải tham chiếu)

Toán tử * dùng để truy cập giá trị tại địa chỉ mà pointer đang trỏ tới. Nó đi đến ô nhớ đó và đọc/ghi giá trị.

Toán tử * — Dereference 
#include 

int main() {
    int a = 10;
    int *p = &a;

    printf("*p = %d\n", *p);  // 10 — lấy giá trị tại địa chỉ p

    *p = 20;  // Sửa giá trị tại địa chỉ p trỏ tới (tức là sửa a)
    printf("a = %d\n", a);    // 20 — a đã thay đổi!

    return 0;
}
Minh họa * và &
a ───▶
10
← Địa chỉ: 0x1000
&a ───▶
0x1000
← Trả về địa chỉ (số của ô nhớ)
*p ───▶
10
← Trả về giá trị tại 0x1000
💡

Cách nhớ đơn giản:
&a → "Địa chỉ của a" (address-of a)
*p → "Giá trị tại địa chỉ p" (value-at-address p)

5

Pass by Value — Truyền theo giá trị

Bạn có một biến a = 5. Bạn muốn viết một hàm change() để đổi giá trị của a thành 10. Điều tưởng chừng đơn giản này lại không hoạt động như bạn nghĩ trong C.

⚠️

Nguyên tắc cốt lõi của C: C luôn truyền tham số theo tham trị (pass by value) — hàm chỉ nhận một bản sao của giá trị, không nhận biến gốc. Đây là điểm quan trọng nhất cần ghi nhớ.

Hãy xem điều gì xảy ra khi bạn truyền a thẳng vào hàm:

C — Truyền tham trị (KHÔNG hoạt động như mong muốn) 
#include 

void change(int x)
{
    x = 10;   // chỉ sửa bản sao, không sửa a
}

int main()
{
    int a = 5;

    change(a);         // truyền GIÁ TRỊ của a (tạo bản sao)

    printf("%d\n", a); // vẫn in ra 5, không thay đổi!
    return 0;
}
Kết quả
5

📌 Tại sao lại ra 5? Hãy xem sơ đồ bộ nhớ:

Khi gọi change(a), chương trình thực hiện như sau:

Bước 1: Tạo bản sao: x = a — lúc này x = 5 (giống a)
Bước 2: Gán x = 10 — chỉ thay đổi x, không ảnh hưởng đến a
Bước 3: Hàm kết thúc — x bị hủy, a vẫn là 5

Sơ đồ bộ nhớ — Trước khi gọi hàm
a ───▶
5
← biến gốc ở ô nhớ 0x1000
Sơ đồ bộ nhớ — Bên trong hàm change()
a ───▶
5
← không đổi, vẫn là 5
x ───▶
10
← bản sao của a, bị sửa thành 10 nhưng sẽ biến mất sau hàm
Hai ô nhớ riêng biệt — a và x không liên quan
a = 5
Ô nhớ: 0x1000
≠
x = 10
Ô nhớ: 0x5000
💡

x là một ô nhớ riêng biệt, nằm ở địa chỉ hoàn toàn khác với a. Sửa x không ảnh hưởng gì đến a vì chúng nằm ở hai địa chỉ bộ nhớ khác nhau. Khi hàm kết thúc, x bị xóa khỏi stack, còn a vẫn nguyên vẹn.

📌 Cách giải quyết "không dùng pointer"

Nếu không dùng pointer, cách duy nhất để lấy giá trị mới từ hàm là trả về giá trị và gán lại:

Cách 1: Trả về giá trị mới — không dùng pointer 
#include 

int change(int x)
{
    x = 10;
    return x;   // trả về giá trị mới
}

int main()
{
    int a = 5;

    a = change(a);  // gán lại giá trị trả về cho a

    printf("%d\n", a); // 10
    return 0;
}
✅

Tóm tắt: Nếu truyền change(a) mà hàm nhận int x thì x là bản sao — không thể sửa a.
Hai giải pháp: (1) Dùng pointer, (2) Trả về giá trị rồi gán lại. Không có cách thứ ba trong C chuẩn.

6

Pass by Address — Truyền theo địa chỉ

Thay vì truyền giá trị (và bị copy), hãy truyền địa chỉ của biến. Hàm sẽ nhận địa chỉ đó và truy cập trực tiếp vào ô nhớ gốc để sửa.

Khai báo hàm nhận con trỏ: void change(int *x) — x giờ lưu một địa chỉ, không phải giá trị.

Gọi hàm với toán tử &: change(&a) — &a lấy địa chỉ bộ nhớ của biến a và truyền nó vào hàm.

Dereference để sửa: *x = 10 — đi đến địa chỉ mà x đang trỏ tới (chính là ô nhớ của a), rồi ghi giá trị 10 vào đó.

C — Dùng Pointer (HOẠT ĐỘNG đúng) 
#include 

void change(int *x)   // x nhận ĐỊA CHỈ của biến
{
    *x = 10;          // dereference: đến địa chỉ đó và ghi 10
}

int main()
{
    int a = 5;

    change(&a);        // &a = lấy địa chỉ của a, truyền vào hàm

    printf("%d\n", a); // in ra 10 — a đã thay đổi!
    return 0;
}
Kết quả
10

📌 Điều gì xảy ra bên trong?

Bước 1: Gọi change(&a) — x nhận địa chỉ của a
x ───▶
địa chỉ của a = 0x1000
──▶
a = 5
Bước 2: Thực thi *x = 10 — sửa trực tiếp ô nhớ của a
x ───▶
địa chỉ của a = 0x1000
──▶
a = 10
✅

x và a cùng trỏ đến một ô nhớ duy nhất. Khi *x = 10, chính ô nhớ của a bị thay đổi — đó là lý do printf("%d\n", a) in ra 10.

📌 So sánh: Pass by Value vs Pass by Address

Tiêu chí Pass by Value (int x) Pass by Address (int *x)
Tham số nhận Bản sao giá trị Địa chỉ của biến gốc
Cách gọi change(a) change(&a)
Ảnh hưởng biến gốc ❌ Không ✅ Có (qua *x)
Dùng khi Chỉ đọc, không cần sửa Cần sửa biến bên ngoài

C++ Reference — Tham chiếu

Trong C++ (không phải C), có thêm một cú pháp gọn hơn gọi là reference (tham chiếu) với ký hiệu & trong khai báo tham số. Nó cho phép bạn thay đổi biến gốc mà không cần dùng pointer.

C++ — Reference (chỉ dùng được trong C++) 
#include 
using namespace std;

// int &x: x là tham chiếu (reference) đến biến được truyền vào
void change(int &x)
{
    x = 10;   // sửa x = sửa trực tiếp biến gốc
}

int main()
{
    int a = 5;

    change(a);         // KHÔNG cần &a — gọi như bình thường

    cout << a << endl; // in ra 10
    return 0;
}
Kết quả
10
Reference: x là bí danh (alias) của a — cùng 1 ô nhớ
x ─┐
. ─┤
Ô nhớ = 10
a ─┘

x và a là hai tên khác nhau của cùng một địa chỉ bộ nhớ. Giống như bạn có biệt danh — dù gọi tên thật hay biệt danh thì vẫn là cùng một người.

🚫

Lưu ý cực kỳ quan trọng: int &x là cú pháp của C++. Nếu bạn đang lập trình C thuần (file .c), cú pháp này sẽ báo lỗi compile. Chỉ dùng được khi compile bằng g++ hoặc file .cpp.

📌 C++ Reference và Pointer tương đương thế nào?

Hai đoạn code sau cho kết quả hoàn toàn giống nhau:

So sánh: C Pointer vs C++ Reference 
// === C (dùng pointer) ===
void change(int *x) {
    *x = 10;
}
// Gọi: change(&a);

// === C++ (dùng reference) ===
void change(int &x) {
    x = 10;
}
// Gọi: change(a);

Kết quả cả hai: a = 10

✅

Tại sao nhiều người thích Reference?
Vì cú pháp gọn hơn: change(a) thay vì change(&a) ở lời gọi, và x = 10 thay vì *x = 10 ở trong hàm.

📌 So sánh chi tiết: Pointer vs Reference

Đặc điểm Pointer (C) Reference (C++)
Khai báo int *p = &a; int &r = a;
Gọi hàm change(&a) change(a)
Thao tác trong hàm *p = 10 r = 10
NULL Có thể NULL Không thể NULL — phải luôn trỏ đến biến hợp lệ
Thay đổi đối tượng trỏ đến Có thể đổi sang trỏ đến biến khác Không thể thay đổi — luôn gắn với cùng 1 biến
Số học (arithmetic) Có thể (p++, p+1, ...) Không thể
Cần dereference Cần (*p) Không cần — dùng trực tiếp
8

Các loại Pointer đặc biệt

Có ba loại pointer đặc biệt mà người mới cần biết để tránh lỗi: NULL pointer, Wild pointer, và Dangling pointer.

📌 NULL Pointer

Con trỏ NULL là con trỏ không trỏ đến bất kỳ địa chỉ hợp lệ nào. Nó có giá trị 0 hoặc (void*)0. Đây là giá trị an toàn để khởi tạo pointer khi chưa dùng ngay.

NULL Pointer — An toàn khi khởi tạo 
#include 
#include 

int main() {
    int *p = NULL;  // p không trỏ đến đâu cả — an toàn

    // Kiểm tra NULL trước khi sử dụng
    if (p == NULL) {
        printf("p đang là NULL, chưa thể dùng\n");
    }

    // Luôn kiểm tra NULL trước khi dereference
    if (p != NULL) {
        printf("%d\n", *p);  // Chỉ thực hiện nếu p không NULL
    } else {
        printf("Không thể dereference p vì p là NULL\n");
    }

    // Ví dụ: malloc trả về NULL nếu không đủ bộ nhớ
    int *arr = malloc(1000000000 * sizeof(int)); // Có thể thất bại
    if (arr == NULL) {
        printf("Không thể cấp phát bộ nhớ!\n");
        return 1;
    }

    return 0;
}
⚠️

Dereference NULL pointer sẽ gây crash chương trình (segmentation fault). Luôn kiểm tra if (p != NULL) trước khi dùng *p.

NULL Pointer — Không trỏ đến đâu
p ───▶
NULL (0)
← Không hợp lệ, dereference sẽ crash

📌 Wild Pointer (Con trỏ hoang)

Wild pointer là con trỏ chưa được khởi tạo, chứa một địa chỉ rác ngẫu nhiên (bất kỳ giá trị nào còn sót lại trong ô nhớ). Dereference nó là undefined behavior — chương trình có thể crash, đọc sai dữ liệu, hoặc tệ hơn là ghi đè dữ liệu quan trọng.

Wild Pointer — NGUY HIỂM — TUYỆT ĐỐI TRÁNH 
#include 

int main() {
    int *p;  // ❌ Wild pointer — chưa khởi tạo, chứa địa chỉ rác

    // printf("%d\n", *p);  // ❌ NGUY HIỂM — có thể crash hoặc đọc rác

    int a = 5;
    p = &a;  // ✅ Bây giờ p đã an toàn, trỏ đến a

    printf("%d\n", *p);  // ✅ 5 — kết quả đúng

    return 0;
}
✅

Best practice: Luôn khởi tạo pointer khi khai báo: int *p = NULL; hoặc gán ngay int *p = &a;. Đừng bao giờ để pointer không được khởi tạo.

Wild Pointer — Chứa địa chỉ rác
p ───▶
0x????
← Giá trị rác — không biết trỏ đến đâu

📌 Dangling Pointer (Con trỏ treo)

Dangling pointer là con trỏ trỏ đến bộ nhớ đã được giải phóng hoặc biến đã ra khỏi scope (biến cục bộ đã bị hủy). Pointer vẫn giữ địa chỉ cũ, nhưng vùng nhớ đó không còn hợp lệ nữa.

Dangling Pointer — Hai trường hợp điển hình 
#include 
#include 

// Trường hợp 1: Trả về địa chỉ của biến cục bộ (stack)
int* createDangling1() {
    int arr[10];  // Biến cục bộ trên stack
    return arr;   // ❌ TRẢ VỀ ĐỊA CHỈ CỦA BIẾN CỤC BỘ — DANGEROUS!
}

// Trường hợp 2: Free bộ nhớ nhưng vẫn dùng pointer
void exampleDangling2() {
    int *q = malloc(sizeof(int) * 10);
    free(q);  // Giải phóng bộ nhớ
    // q bây giờ là dangling pointer
    // q[0] = 5;  // ❌ NGUY HIỂM — use after free
    q = NULL;  // ✅ Sau khi free, gán NULL ngay lập tức
}

int main() {
    // Dùng pointer trả về từ hàm
    int *p = createDangling1();
    // p là dangling pointer — arr đã bị hủy
    // printf("%d\n", p[0]);  // ❌ Undefined behavior

    exampleDangling2();
    return 0;
}

Array & Pointer — Mối liên hệ mật thiết

Trong C, tên mảng thực chất là một con trỏ hằng (constant pointer) trỏ đến phần tử đầu tiên của mảng. Đây là lý do bạn có thể dùng pointer để thao tác với mảng.

Mảng và Pointer tương đương nhau 
#include 

int main() {
    int arr[] = {10, 20, 30, 40, 50};
    int *p = arr;  // p trỏ đến phần tử đầu tiên của arr (arr[0])

    // === Các cách truy cập tương đương ===
    printf("Cách 1: arr[0] = %d\n", arr[0]);        // 10
    printf("Cách 2: *arr = %d\n", *arr);             // 10
    printf("Cách 3: p[0] = %d\n", p[0]);             // 10
    printf("Cách 4: *p = %d\n", *p);                 // 10

    // Truy cập phần tử thứ 3 (index 2):
    printf("arr[2] = %d\n", arr[2]);                 // 30
    printf("*(arr + 2) = %d\n", *(arr + 2));         // 30
    printf("p[2] = %d\n", p[2]);                     // 30
    printf("*(p + 2) = %d\n", *(p + 2));             // 30

    return 0;
}
💡

arr[i] thực chất là *(arr + i) — đi đến địa chỉ arr + i (tự động nhân với sizeof(int)) rồi lấy giá trị tại đó. Đây là lý do arr[0] tương đương *arr.

⚠️

Khác biệt quan trọng giữa arr và p:
arr là con trỏ hằng (constant pointer) — không thể gán arr = p hay arr++. Bạn chỉ có thể dùng nó để đọc.
p là biến pointer bình thường — có thể thay đổi, gán lại, hay tăng giảm.

Pointer Arithmetic — Số học con trỏ

Bạn có thể thực hiện các phép toán cộng, trừ trên pointer. Khi cộng/trừ, pointer sẽ tự động nhân với kích thước kiểu dữ liệu (sizeof). Điều này rất hữu ích khi duyệt mảng.

Pointer Arithmetic với mảng int 
#include 

int main() {
    int arr[] = {10, 20, 30, 40, 50};
    int *p = arr;

    printf("p = %p\n", p);         // 0x1000 (giả sử)
    printf("p + 1 = %p\n", p + 1); // 0x1004 (tăng 4 bytes vì sizeof(int) = 4)
    printf("p + 2 = %p\n", p + 2); // 0x1008
    printf("p + 3 = %p\n", p + 3); // 0x100C

    // Truy cập giá trị qua pointer arithmetic:
    printf("*p = %d\n", *p);           // 10
    printf("*(p+1) = %d\n", *(p+1));   // 20
    printf("*(p+2) = %d\n", *(p+2));   // 30

    // Duyệt mảng bằng pointer
    printf("Duyệt mảng: ");
    for (int *q = arr; q < arr + 5; q++) {
        printf("%d ", *q);  // 10 20 30 40 50
    }
    printf("\n");

    // Pointer subtraction: trả về SỐ PHẦN TỬ, không phải bytes
    int *q = &arr[4];
    printf("q - p = %ld\n", q - p); // 4 (có 4 phần tử giữa p và q)

    return 0;
}

0x1004
20 ← p+1
0x1008
30 ← p+2
0x100C
40 ← p+3
0x1010
50 ← p+4

Mỗi lần p + 1, địa chỉ tăng 4 bytes (kích thước của int). Nếu là char, chỉ tăng 1 byte.

Bảng quy đổi — p + 1 tăng bao nhiêu?

Kiểu dữ liệu sizeof p + 1 tăng (bytes) Ví dụ địa chỉ

short * 2 bytes +2 bytes 0x1000 → 0x1002

long * 8 bytes (trên 64-bit) +8 bytes 0x1000 → 0x1008
double * 8 bytes +8 bytes 0x1000 → 0x1008

malloc và free — Cấp phát bộ nhớ động

Khi bạn cần cấp phát bộ nhớ tại runtime (kích thước không biết trước, hoặc cần dữ liệu tồn tại lâu hơn scope của hàm), dùng malloc() để cấp phát trên heap và free() để giải phóng.

malloc và free — Cấp phát mảng động 
#include 
#include 

int main() {
    int n;

    printf("Nhập số phần tử: ");
    scanf("%d", &n);

    // Cấp phát mảng n số nguyên trên heap
    int *arr = (int*)malloc(n * sizeof(int));

    // Luôn kiểm tra malloc có thành công không
    if (arr == NULL) {
        printf("Không thể cấp phát bộ nhớ!\n");
        return 1;
    }

    // Sử dụng như mảng bình thường
    for (int i = 0; i < n; i++) {
        arr[i] = (i + 1) * 10;
    }

    printf("Mảng: ");
    for (int i = 0; i < n; i++) {
        printf("%d ", arr[i]);
    }
    printf("\n");

    // QUAN TRỌNG: Giải phóng bộ nhớ khi không dùng nữa
    free(arr);
    arr = NULL;  // Tránh dangling pointer

    return 0;
}
Stack vs Heap — Bộ nhớ được quản lý thế nào
Stack ───▶
arr (pointer: 0x5000)
n
...biến cục bộ
← Tự động quản lý, cấp phát và giải phóng khi hàm kết thúc
Heap ───▶
arr[0]
arr[1]
...
arr[n-1]
← Bạn phải tự quản lý bằng malloc/free
✅

3 Best practices khi dùng malloc/free:
1. Luôn kiểm tra malloc() trả về NULL (hết bộ nhớ)
2. Luôn free() bộ nhớ khi không dùng nữa — nếu quên sẽ gây memory leak
3. Sau free(), gán pointer = NULL để tránh dangling pointer

⚠️

Memory leak là gì? Nếu bạn malloc() mà quên free(), bộ nhớ sẽ không được trả về cho hệ thống. Nếu chương trình chạy lâu, nó sẽ tiêu tốn ngày càng nhiều RAM cho đến khi đầy. Dùng Valgrind để phát hiện memory leak:

$ valgrind ./program

Struct Pointer — Con trỏ đến struct

Khi làm việc với struct, pointer giúp tránh copy toàn bộ struct khi truyền vào hàm — chỉ truyền địa chỉ (8 bytes), tiết kiệm bộ nhớ và thời gian, đặc biệt với struct lớn.

Struct Pointer và toán tử -> 
#include 
#include 

typedef struct {
    char name[50];
    int age;
    float gpa;
} Student;

// ❌ Cách 1: Truyền cả struct (copy toàn bộ — tốn bộ nhớ)
void printStudent(Student s) {
    printf("Tên: %s - %d tuổi - GPA: %.2f\n", s.name, s.age, s.gpa);
}

// ✅ Cách 2: Truyền pointer (chỉ truyền địa chỉ — nhanh, tiết kiệm)
void printStudentPtr(const Student *s) {
    // Dùng (*s).name hoặc s->name — cả hai đều được
    printf("Tên: %s - %d tuổi - GPA: %.2f\n", s->name, s->age, s->gpa);
}

// ✅ Dùng -> operator để sửa field
void updateGPA(Student *s, float newGPA) {
    s->gpa = newGPA;  // Tương đương (*s).gpa = newGPA
}

int main() {
    Student sv1 = {"Nguyen Van A", 20, 3.5};

    // Cách 1: Copy cả struct (kém hiệu quả với struct lớn)
    printStudent(sv1);

    // Cách 2: Chỉ truyền địa chỉ (hiệu quả)
    printStudentPtr(&sv1);

    // Sửa field qua pointer
    updateGPA(&sv1, 3.8);
    printf("GPA mới: %.2f\n", sv1.gpa);  // 3.8

    return 0;
}
Struct Pointer — Tránh copy, chỉ truyền địa chỉ
sv1 ───▶
name: "Nguyen Van A"
age: 20
gpa: 3.5
← Toàn bộ struct (~58 bytes)
ptr ───▶
địa chỉ của sv1
← Chỉ truyền 8 bytes (địa chỉ), không copy struct
💡

Toán tử ->: s->name tương đương (*s).name — dereference rồi truy cập field. Toán tử -> ngắn gọn và dễ đọc hơn, đặc biệt khi có nhiều field. Hãy luôn dùng -> với struct pointer.

Const Pointer — Con trỏ hằng

Có 3 kiểu kết hợp const với pointer, mỗi kiểu có ý nghĩa và ràng buộc khác nhau. Đây là chủ đề gây nhầm lẫn nhất cho người mới.

📌 Cách đọc khai báo const pointer

Quy tắc: Đọc từ phải sang trái. const áp dụng cho phần tử đứng ngay bên trái nó.

Kiểu Khai báo Đọc từ phải sang trái Có thể...
1. Pointer to const const int *p
int const *p		 "p là pointer đến int const" ✅ p = &b (đổi pointer)
❌ *p = 10 (không sửa giá trị)
2. Const pointer int * const p = &a "p là const pointer đến int" ❌ p = &b (không đổi pointer)
✅ *p = 10 (sửa giá trị)
3. Const pointer to const const int * const p = &a "p là const pointer đến int const" ❌ p = &b (không đổi pointer)
❌ *p = 10 (không sửa giá trị)
3 kiểu Const Pointer — Ví dụ chi tiết 
#include 

int main() {
    int a = 5, b = 10;

    // === 1. Pointer to const ===
    // Không thể sửa giá trị qua pointer, nhưng có thể đổi pointer
    const int *p1 = &a;
    // *p1 = 20;  // ❌ Lỗi: không thể sửa giá trị qua p1
    p1 = &b;       // ✅ OK: có thể đổi pointer sang biến khác
    printf("*p1 = %d\n", *p1); // 10 (giá trị của b)

    // === 2. Const pointer ===
    // Có thể sửa giá trị, nhưng không thể đổi pointer
    int * const p2 = &a;
    *p2 = 20;      // ✅ OK: có thể sửa giá trị (a = 20)
    // p2 = &b;    // ❌ Lỗi: không thể đổi pointer
    printf("a = %d\n", a); // 20

    // === 3. Const pointer to const ===
    // Không thể sửa giá trị, cũng không thể đổi pointer
    const int * const p3 = &a;
    // *p3 = 30;   // ❌ Lỗi: không thể sửa giá trị
    // p3 = &b;    // ❌ Lỗi: không thể đổi pointer
    printf("*p3 = %d\n", *p3); // 20

    return 0;
}
💡

Mẹo nhớ: Đọc từ phải sang trái và nhìn chữ const:
- const int *p → "con trỏ đến int const" → int là const
- int * const p → "con trỏ const đến int" → pointer là const
- const int * const p → "con trỏ const đến int const" → cả hai đều const

Tình huống Nên dùng Lý do
Hàm chỉ đọc dữ liệu, không sửa const int *p Đảm bảo không vô tình sửa dữ liệu
Hàm cần sửa dữ liệu tại địa chỉ cố định int * const p Đảm bảo pointer không bị đổi
Hằng số toàn cục const int * const p Bảo vệ tuyệt đối khỏi sửa đổi

10 Lỗi Pointer thường gặp và cách khắc phục

Dưới đây là 10 lỗi phổ biến nhất khi làm việc với pointer mà người mới học thường gặp, kèm cách phòng tránh và sửa lỗi.

  • Dereference NULL pointer

    Truy cập giá trị qua pointer NULL sẽ gây segmentation fault — chương trình crash ngay lập tức.

    int *p = NULL;
    printf("%d\n", *p); // ❌ SEGMENTATION FAULT — crash

    ✅ Fix: Luôn kiểm tra NULL trước khi dereference: if (p != NULL) { ... }

  • Dereference uninitialized pointer (Wild pointer)

    Pointer chưa khởi tạo chứa địa chỉ rác. Dereference nó dẫn đến undefined behavior — có thể crash, sai kết quả, hoặc tệ hơn là ghi đè dữ liệu quan trọng.

    int *p; // Chưa khởi tạo — chứa rác
    *p = 10; // ❌ Undefined behavior — ghi vào địa chỉ rác

    ✅ Fix: Luôn khởi tạo pointer ngay khi khai báo: int *p = NULL; hoặc int *p = &a;

  • Dangling pointer (Use after free)

    Sử dụng pointer sau khi đã free bộ nhớ. Pointer vẫn giữ địa chỉ cũ, nhưng vùng nhớ đó đã được trả về hệ thống.

    int *p = malloc(sizeof(int));
    free(p);
    *p = 10; // ❌ Use after free — undefined behavior

    ✅ Fix: Sau free(), gán ngay p = NULL; — free(NULL) là an toàn (no-op).

  • Memory leak (Rò rỉ bộ nhớ)

    malloc() mà không free(). Bộ nhớ không được trả lại, chương trình tốn dần RAM cho đến khi đầy.

    void func() {
      int *p = malloc(1000);
      // Quên free(p); — memory leak!
    } // Mỗi lần gọi func() mất 1000 bytes vĩnh viễn

    ✅ Fix: Luôn free bộ nhớ khi không dùng. Dùng Valgrind để kiểm tra: valgrind ./program

  • Return address of local variable

    Trả về địa chỉ của biến cục bộ. Khi hàm kết thúc, biến cục bộ bị hủy, địa chỉ trở nên không hợp lệ.

    int* func() {
      int a = 5;
      return &a; // ❌ Dangling pointer — a bị hủy khi hàm kết thúc
    }

    ✅ Fix: Dùng malloc để cấp phát trên heap, hoặc truyền pointer vào hàm để nhận kết quả.

  • Pointer arithmetic sai kiểu / nhầm lẫn

    Cộng pointer với số bytes thay vì số phần tử. Hoặc nhầm lẫn giữa các kiểu dữ liệu.

    int arr[10];
    int *p = arr;
    p = p + 4; // ✅ Tăng 4 phần tử (16 bytes với int)
    // p = (int*)((char*)p + 4); // ❌ Ý đồ: chỉ tăng 4 bytes = 1 phần tử

    ✅ Fix: Hiểu rằng p+1 tăng sizeof(type) bytes. Với int, p+1 = +4 bytes.

  • Nhầm lẫn giữa * trong khai báo và * dereference

    Dấu * trong int *p (khai báo) khác với *p = 10 (dereference). Nhầm lẫn dẫn đến khai báo sai nhiều biến.

    int* p, q; // ❌ Chỉ p là pointer, q là int
    // Đúng: int *p, *q; hoặc int *p; int *q;
    *p = 5; // OK — p là pointer
    q = 10; // OK — q là int, không phải pointer

    ✅ Fix: Khai báo mỗi biến trên một dòng riêng, hoặc nhớ dấu * gắn với từng biến.

  • Quên & khi truyền vào hàm cần sửa biến

    Hàm nhận int *x (cần địa chỉ) nhưng bạn lại truyền a (giá trị) thay vì &a (địa chỉ).

    void change(int *x) { *x = 10; }
    int a = 5;
    change(a); // ❌ Sai: truyền giá trị (int) nhưng hàm cần địa chỉ (int*)
    change(&a); // ✅ Đúng: truyền địa chỉ

    ✅ Fix: Khi muốn hàm sửa biến, luôn dùng & ở lời gọi: change(&a).

  • Array-Pointer confusion

    Nhầm tên mảng với pointer — không thể gán mảng hay increment mảng vì mảng là const pointer.

    int arr[10];
    int *p = arr; // ✅ OK: arr decay thành pointer
    arr = p; // ❌ Lỗi: arr là const pointer, không thể gán
    arr++; // ❌ Lỗi: không thể increment array

    ✅ Fix: Hiểu rằng tên mảng là const pointer — chỉ đọc, không ghi đè. Dùng biến pointer riêng để thao tác.

  • Double free (Free cùng một pointer hai lần)

    Free cùng một địa chỉ hai lần gây hỏng heap manager, dẫn đến crash khó debug.

    int *p = malloc(100);
    free(p);
    free(p); // ❌ Double free — undefined behavior, thường crash

    ✅ Fix: Sau free, gán p = NULL. Free(NULL) là an toàn (không làm gì cả).

🛡️

5 Chiến lược phòng ngừa lỗi pointer:
1. Luôn khởi tạo pointer khi khai báo (int *p = NULL)
2. Kiểm tra NULL trước khi dereference.
3. Free bộ nhớ và gán NULL ngay sau đó.
4. Dùng tools như Valgrind để detect memory leaks và lỗi.
5. Compile với đầy đủ warnings: gcc -Wall -Wextra -pedantic
